# RAG Mock Module

Demo module for testing the full RAG compliance analysis pipeline end-to-end. Contains 5 sample contracts with deliberate compliance gaps that should trigger violations against the seeded rulesets.

## What Is This?

The RAG (Retrieval-Augmented Generation) mock provides:

- **5 sample contracts** — Realistic contract text with intentional compliance gaps (probation too long, missing gratuity, PDPL violations, etc.)
- **5 seeded rulesets** — UAE Labour Law, DMCC Employment, PDPL, Commercial Transactions, DIFC Employment
- **Pre-computed embeddings** — Ruleset chunks with vector embeddings for similarity search (either via seed or live ingestion)

The analysis flow: upload contract → worker-ai embeds it → hybrid search (vector + BM25) against `ruleset_chunks` → LLM compares contract vs. retrieved rules (structured output) → returns violations.

## Prerequisites

You need ruleset chunks (with embeddings) in `ruleset_chunks`. Two options:

### Option A: Use Pre-Seeded Chunks (Recommended for Quick Setup)

1. **Seed everything** — `pnpm db:seed` (runs 001–010, including `010_seed_ruleset_chunks.sql`)
2. Chunks are already in the DB — no ingestion or worker-ingestion needed for the 5 demo rulesets.
3. **Start API + worker-ai only** — `pnpm dev:all` (worker-ingestion optional if you only use seeded chunks)

### Option B: Ingest Rulesets Live (Requires worker-ingestion)

1. **Seed rulesets only** — run `009_seed_rulesets.sql` (or `pnpm db:seed` and skip 010)
2. **Ingest the rulesets** — trigger ingestion so vector chunks are created:
   ```bash
   # For each of the 5 rulesets, call POST /rulesets/:key/ingest as a system admin:
   curl -X POST http://localhost:3000/rulesets/uae_labour_law_employment_v1/ingest
   curl -X POST http://localhost:3000/rulesets/dmcc_employment_regulations_v1/ingest
   curl -X POST http://localhost:3000/rulesets/uae_data_protection_pdpl_v1/ingest
   curl -X POST http://localhost:3000/rulesets/uae_commercial_transactions_v1/ingest
   curl -X POST http://localhost:3000/rulesets/difc_employment_law_v1/ingest
   ```
3. **Wait for ingestion** — check the `data-ingestion` queue or worker-ingestion logs.
4. **Start all apps** — `pnpm dev:all` (API + worker-ai + worker-ingestion).

## Regenerating the Chunk Seed (010_seed_ruleset_chunks.sql)

The file `scripts/seeds/010_seed_ruleset_chunks.sql` contains pre-computed embeddings for the 5 demo rulesets. It is generated by:

```bash
pnpm db:generate-chunk-seed
```

**When to run it:**

- After changing ruleset content in `009_seed_rulesets.sql`
- After changing the embedding model or chunking logic
- To refresh the seed after manual ingestion (exports from DB → SQL file)

**Requirements:**

- Database running with chunks already in `ruleset_chunks` (run Option B ingestion first, or use an existing DB that has them)
- Env vars from `apps/api/.env` (DB_HOST, DB_PORT, etc.)

**Output:** Overwrites `scripts/seeds/010_seed_ruleset_chunks.sql` (~800KB). Safe to commit — embeddings are deterministic for the same input.

## Endpoints

All endpoints require a **tenant access token** (cookie-based JWT).

### List sample contracts

```
GET /rag-mock/contracts
```

Returns index, title, content preview, and length for all 5 contracts.

### Analyze a sample contract

```
POST /rag-mock/analyze/:contractNumber
```

- `contractNumber` — integer from 1 to 5
- Returns `202 Accepted` with `{ documentId, analysisJobId }`
- Poll `GET /documents/:documentId/analysis` for status and results

## Architecture

```
rag-mock/
├── rag-mock.module.ts            Module — imports DocumentsModule
├── rag-mock.controller.ts        Controller — GET /contracts, POST /analyze/:n
├── sample-contracts.constant.ts  5 sample contracts with compliance gaps
└── README.md                     This file
```

The controller delegates to `DocumentsService.analyze()`, which creates a `documents` row, an `analysis_jobs` row, and enqueues a job on the `ai-processing` queue. The `worker-ai` picks it up, runs hybrid search (vector + BM25 via RRF) against `ruleset_chunks`, builds a prompt, calls the LLM with structured output (JSON Schema), and writes results back to `analysis_jobs.result`.

## Debugging & Observability

### Bull Board (Queue Dashboard)

The API exposes **Bull Board** at `http://localhost:3010/admin/queues` (its own port, `BULL_BOARD_PORT`) for visual queue monitoring. You can inspect:

- `ai-processing` — analysis jobs (pending, active, completed, failed)
- `data-ingestion` — ruleset ingestion jobs
- `entitlement-processing` — entitlement async jobs
- `billing-processing` — billing reconciliation jobs
- `tenant-processing` — tenant lifecycle jobs

### Worker Logs

Each worker logs job lifecycle and pipeline stages to stdout:

**worker-ai** (`DocumentAnalysisService`, `AbstractProcessor`):

- Job started/completed (with job id, attempt, elapsed ms)
- Pipeline stages: document fetch, chunking, embedding, hybrid search, re-rank, LLM call, result storage
- Job failed (retryable vs permanent), exhausted retries, dead letter

**worker-ingestion** (`RulesetIngestionService`, `AbstractProcessor`):

- Job started/completed
- Ingestion stages: ruleset fetch, clause chunking, embedding, DB upsert
- Warnings: empty clauses, dropped invalid clauses

Run `pnpm dev:all` and watch the worker terminal output when triggering analysis or ingestion.

### Seed Scripts

Seed scripts emit `RAISE NOTICE` on completion (e.g. `Ruleset chunks seeded: N`). Check the `pnpm db:seed` output for verification.
